# Frontends

Both apps use React 19, TypeScript, Vite 8, Tailwind CSS 3, TanStack React Query,
and API clients generated by `@hey-api/openapi-ts`.

## Chat frontend (`frontends/chat-frontend/`)

Demo chat UI that talks to an agent app (Quarkus, Spring, Python, TypeScript
examples), which proxies Memory Service agent APIs. The Maven wrapper module is
`java/chat-frontend/pom.xml`; it only packages `frontends/chat-frontend/dist`.

```
src/
├── App.tsx                     # Layout, sidebar data, conversation selection
├── components/
│   ├── conversation.tsx        # Headless chat primitives and ChatEvent types
│   ├── conversations-ui/index.tsx  # Tailwind-styled wrappers, attachments
│   ├── chat-panel.tsx          # Messages, input, fork navigation, sharing
│   ├── chat-sidebar.tsx        # Conversation list and child sub-navigation
│   ├── rich-event-renderer.tsx # Text/thinking/tool event cards
│   ├── sharing/  ui/           # Membership modals, Radix-based primitives
├── hooks/                      # useSseStream, useEventStream, useResumeCheck, ...
├── lib/                        # auth.tsx, langchain-events.ts, profile-context.ts
└── client/                     # Generated OpenAPI client (do not edit)
```

- Headless pattern: `conversation.tsx` provides unstyled primitives and hooks;
  `conversations-ui/index.tsx` styles them. Change logic in the former, looks in
  the latter.
- Theme in `tailwind.config.js`: `cream`, `ink`, `mist`, `stone`, `terracotta`,
  `sage`. Use `cn()` from `lib/utils.ts` to merge classes.
- React Query holds server state; auth and conversation state live in context.
- Agent-app endpoints beyond the baseline (for example `/v1/profile-context`)
  are optional; feature-detect them instead of assuming they exist.

## Developer frontend (`frontends/developer/`)

Admin/auditor console built on the admin API (`contracts/openapi/openapi-admin.yml`)
with TanStack Router file-based routes in `src/routes/` (`routeTree.gen.ts` is
generated and gitignored, so `npm run build` runs `vite build` before `tsc -b`).

- Served under the `/developer` base path. Navigate with TanStack Router links
  or `useNavigate`; never use root-relative `window.location` URLs, which drop
  the base path.
- Runtime config comes from `/config.json`; auth is OIDC or a development-only
  API key (`src/lib/auth.tsx`, headers in `src/api/client.ts`).
- Data hooks live in `src/hooks/` (`useAdminApi.ts`, `useLineageEntries.ts`).
- Design tokens (cream, sage, terracotta) are in `tailwind.config.js`.

## Generated API clients

- Regenerate with `npm run generate` in the affected app after contract changes
  under `contracts/openapi/`. Never hand-edit `src/client/` or `src/api/generated/`.
- Keep the generated React Query helpers' typed object query keys; do not
  replace them with string-array keys.
- Service return unions may include `ErrorResponse` even though the runtime
  client throws on non-2xx responses (`throwOnError: true`). Use a deliberate
  `unknown` cast to the success type rather than weakening generated schemas.
- The generated `auth` callback is called for every declared security scheme,
  including alternatives. Token resolvers must check `auth.scheme` (the chat
  app returns its OIDC token only for `"bearer"`), or the token gets sent as
  `X-API-Key`.

## Verification

```bash
# chat-frontend has no test runner
cd frontends/chat-frontend && npm run lint && npm run build   # or: task test:chat-frontend

# developer frontend uses vitest
cd frontends/developer && npm run lint && npm test && npm run build   # or: task test:developer-frontend
```

Run `npm ci` first if `node_modules` is missing.
