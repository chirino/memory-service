Memory Service can export durable lifecycle events and current-state records to an analytics database. The processor runs outside the request path, so an analytics outage does not delay application writes.

ClickHouse is the supported analytics provider. The processor reads the admin durable event stream, fetches bounded source records, writes batches to ClickHouse, and saves its safe cursor through `AdminCheckpointService`.

## Choose what to export

The payload mode controls which source data crosses into the analytics system.

| Mode        | Data written                                                                            | Use it for                                                             |
| ----------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `metadata`  | Source identifiers, timestamps, lifecycle fields, routing fields, and selected metadata | Operational dashboards that do not need entry content or memory values |
| `projected` | Metadata plus fields released by immutable projection manifests                         | Domain analytics with an explicit schema and data boundary             |
| `full`      | Decrypted source snapshots                                                              | Controlled environments that require the complete source record        |

The repository deployments use `metadata` by default. Use `projected` when analysts need approved fields from an entry `contentType` or a memory `kind`. Full mode requires `--allow-decrypted-content` because Memory Service field encryption does not extend to ClickHouse.

## Understand the exported data

The processor creates generic tables for conversations, lineage, entries, memories, and lifecycle events. A projection adds a deployment-owned table for one exact entry `contentType` or memory `kind`.

Generic resources use these canonical views:

- `conversations_current`, `entries_current`, and similar resource views return the latest logical non-deleted row.
- `resources_all` returns the latest logical generic row, including a deletion tombstone when one is current.

Projection tables provide both `<name>_current` and `<name>_all` views. Physical tables retain versioned rows until retention or a hard-delete purge removes them. Queries for application dashboards should normally use a canonical view.

Projection names and column names map directly to SQL identifiers. A projection named `support_ticket_v1` creates these relations:

- `support_ticket_v1`, the physical table
- `support_ticket_v1_all`, the latest logical row including tombstones
- `support_ticket_v1_current`, the current non-deleted row

## Keep the trust boundary explicit

ClickHouse is a separate persistence boundary. Configure its storage, replicas, backups, caches, temporary files, and disaster-recovery copies to meet the same deletion and encryption requirements as Memory Service.

The processor stores Memory Service source identifiers in ClickHouse so analytics results can link back to authoritative records through the Memory Service API. Grant ClickHouse access accordingly. Payload modes and projection manifests control which source fields accompany those identifiers.
